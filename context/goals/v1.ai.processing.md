## Task brief · docproc

```
Problem       Nothing writes or reads a docproc run directory. The library is tagged
              v0.1.0 with its stores, its stages, and the dispatcher's pool, but it has
              no command that runs the whole suite over an input set and no public
              package that reads the result. docinfer's cmd/docinfer, in another
              repository, needs one, and so do the reports and acceptance tasks. The
              spike's command (spike-ai-pipeline at 6a631f1) has several flaws:
              - It writes schema "1".
              - It buffers its record, so a killed run leaves an unreadable file and
                its readers pick the killed run as the latest.
              - It copies a seen part's subtree out of earlier records.
              - It treats an index failure as one input's error and exits 0.
              - Its run directory carries no version of its own.
              - It probes every tool before checking its inputs.
              The design review settled all of this (DP-1 to DP-25, SH-6, SH-8): rundir
              and rundir/schema become public packages of the base module, under schema
              "2". cmd/docproc becomes a nested module that requires them, and the base
              module is tagged v0.2.0 once they land. The library leaves every bound
              unset, so the command must ship the operator's starting values.
              Nothing trails: currency reports only the three recorded holds.
Behaviors     1. rundir/schema, shapes alone, importing no docproc package but dispatch
                 and inspect:
                 - Version is "2", which includes dispatch's shapes at dispatch.Version
                   "1".
                 - Event carries dispatch.Event's fields inline, beside its kind (part,
                   output, warning, error), its input argument, its File, its
                   quarantine, its Span, and an error line's text. An error line has no
                   part.
                 - File holds an input's file metadata and `detected`, its sniffed type.
                 - The manifest keeps schema and run, drops record, and gains docproc
                   (the command's module version and the library's) and collected (the
                   number of inputs the arguments named). Its tools and stage table are
                   dispatch's Tool and Row.
                 - Every Time is UTC, made by TimeOf, which converts any zone. The tests
                   run under a non-UTC zone.
              2. rundir's reader:
                 - Open reads and creates nothing. It fails matching fs.ErrNotExist on a
                   root that is no run directory. It refuses another schema, or runs
                   with no rundir.json, naming both versions.
                 - Runs lists the runs alone, in order. Latest is the latest run that
                   ended.
                 - Manifest and Record refuse an id that isn't a run of the directory.
                 - Record yields the lines in order and ends on the first that doesn't
                   decode. For an unended run it drops a last line with no newline, and
                   it says that a run given by id has not ended.
                 - Content is the run directory's FileContent. ContentPath is the
                   content directory joined to dispatch.ContentFile.
              3. rundir's writer:
                 - Create makes the directory, rundir.json, the index, and the content
                   store when they are absent. Over an existing directory it refuses as
                   Open does.
                 - Begin removes the work directories a killed run left.
                 - Write appends one line, written through as one write with no fsync,
                   so a killed run loses at most its last line.
                 - End records the run's end and its error.
                 - Quarantine keeps a part's file once, named by its SHA-256.
                 - The package documents that one process writes a run directory.
                 - A committed schema "2" run directory is read through the reader and
                   written again through the writer, compared as text.
              4. cmd/docproc's module:
                 - It requires docproc, go-cli-sdk v0.4.0, go-core v0.12.0, and
                   golang.org/x/sys alone.
                 - Its main sits at the module's root, so `go install
                   …/cmd/docproc@<version>` installs it. Its composition root and
                   fixtures are internal, started from go-cli-sdk-template's
                   template/v0.3.0.
                 - `docproc version` prints the module's version and builds nothing.
                 - Help and usage errors exit 2.
                 - The committed go.work and the check's module list both name it, and
                   the check runs it outside the workspace.
                 - Each module's import allowlist admits only that module's own
                   requirements. The base module imports no cmd/docproc package.
                 - CI's Go job runs on a change to it.
                 - During BUILD it reaches the unreleased base module through a
                   temporary replace.
              5. Starting bounds, from one configuration node read from DOCPROC_
                 variables:
                 - Each bound is one variable. No name repeats a live tier's variables.
                 - Each default is a starting value:
                   - memory 2 GiB
                   - unit-run Timeout 10 min; stream-run Idle 2 min
                   - 100,000 parts, 32 GiB, depth 16
                   - bomb rule 1000:1 past 1 GiB; archive Entries 100,000
                   - claim Release 10 s
                   - pages and windows held: 1
                   - DPI 150, with the text layer read; MaxPixels 64 million
                   - a video frame's largest side 2048
                   - ImageMagick: area 256 MP, memory 1 GiB, map 2 GiB, disk 8 GiB
                 - A duration is read as a Go duration and a size as a count of bytes.
                 - A value it can't take fails the run before any tool is probed,
                   naming its variable. A command that declares no node reads none.
                 - The README lists each variable and its starting value.
              6. `docproc run <path>... --out <dir>`, collecting its inputs:
                 - A file argument is one input, and a directory yields each regular
                   file under it, in lexical order, each file once.
                 - A named argument that is a symbolic link is followed, and links under
                   a directory are not.
                 - The run fails before any tool is probed on an argument that is
                   neither a file nor a directory, or on arguments that yield no input.
                 - --workers is at least 1, with no ceiling, defaulting to the host's
                   CPUs.
                 - --exclude repeats, naming a route to leave out. An unknown route is a
                   usage error.
              7. `docproc run` dispatching:
                 - It builds the stages over the host's tools, through a stage-builder
                   node that the fixtures replace, and prints the stage table.
                 - It creates the run directory and begins a run whose manifest names
                   its tools, its stage table, and the number collected.
                 - It writes one record line per pool event, in order:
                   - each output's content is in the run directory's content store;
                   - a seen part's log is replayed by the dispatcher, children included;
                   - an input's part line carries its File (Statx, birth time where the
                     kernel gives one, and the detected type) and its time from its
                     first event to its last;
                   - a quarantined part's file is kept, and every line names it while it
                     exists;
                   - an input stopped before its own event is an error line.
                 - A store's failure stops the run, ends it with the error, and exits 1.
                   Failed parts and error inputs exit 0, as the help states. The
                   summary's last line counts both.
                 - A canceled run ends its manifest with the cancellation. Its record
                   stays readable.
              8. The built-binary integration tier, under the integration tag, run by
                 test:integration over the tools built from the checkout:
                 - A run over the repository's committed fixtures writes a schema "2"
                   directory that rundir.Open reads, every input accounted for.
                 - A run killed by SIGKILL partway through its record still reads
                   through Record, losing at most its torn last line. Latest skips it,
                   and Record says it has not ended.
                 - When the fixture tree is absent, the tier skips, naming what is
                   missing.
              9. Release:
                 - The README lists rundir and rundir/schema, names stages as the
                   shipped wiring and cmd/docproc as its first caller, and states the
                   command and its configuration.
                 - STANDARDS.md states the exception: the nested command's main sits at
                   its module's root, and its packages are internal.
                 - The base module's CHANGELOG gets a dated [v0.2.0].
                 - cmd/docproc's CHANGELOG starts at [Unreleased], citing the spike at
                   6a631f1.
                 - layers.md states rundir and cmd/docproc as built.
                 - After the tag, cmd/docproc requires v0.2.0, and no replace remains.
Test seams    rundir's reader and writer API over its committed run directory;
              cmd/docproc's App, run through apptest with the stand-in tools and stage
              builder; the built binary through the integration tier; each module's
              `mise run check`; `mise run test:integration`; CI on each pull request
Slices        1 rundir/schema
              2 rundir: reader and writer, with the committed run directory
              3 cmd/docproc's module: the template's composition root, version, go.work,
                the check's module list, import allowlists, the CI filter, and the
                temporary replace
              4 starting bounds: the configuration node and its variables
              5 run: collecting inputs, the stage table, the pool into the record, File
                and quarantine, store failure, and the summary
              6 integration tier: the fixture run and the killed run
              7 release: README, STANDARDS.md, CHANGELOGs, and layers.md. At SHIP:
                - merge with the replace;
                - tag v0.2.0 on main;
                - a second pull request swaps the replace for v0.2.0, and merges once CI
                  is green.
Out of scope  the report command and its pages (reports); the cmd/docproc/v0.1.0 tag
              (reports); bound values measured over ~/docs (acceptance); cmd/docinfer's
              move to schema "2" (the docinfer goal); reading schema "1" directories;
              architecture page edits (the sync); go.work.sum
Door          one-way for the v0.2.0 tag (rundir's public API is then in the module
              proxy and checksum database, and can only be retracted); two-way for the
              rest (code, the temporary replace and its swap, CI, mise tasks, context
              edits)
Release       docproc: v0.2.0
```
