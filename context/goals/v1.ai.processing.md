## Task brief · v1.ai.processing · final

**Problem**

This is the goal's last task. The record of what docproc delivers must come from reruns against
the releases hardening and mail-hardening cut: cmd/docproc over ~/docs, the mail bench, and the
shared-gs identity check. Three of the summary's premises have moved:

- The two default container images compiled into the base module trail and sit outside currency:
  Gotenberg 9.1.0 for soffice, and linuxserver/ffmpeg 9.0.2-cli-ls89, whose pin an integration
  test also copies.
- storage, postgres, and docproc-onenote hold unreleased changes.
- The architecture README already lists go-ai, docproc, and docinfer ("Four libraries", 60dcc3d),
  so nothing there is left to do.

Acceptance's ~/docs run directory no longer exists, and v1.ai.inference's acceptance needs a run
to read. The goal's standing rules apply:

- what currency trails is taken;
- known breakage is fixed before the tag;
- found improvements land here;
- performance has no metric bar.

**Behaviors**

1. Currency reports, and upgrade moves, every container image pinned in the module's Go source:
   the soffice and ffmpeg defaults and each test's copy of them.
   - They are read by the compose pins' rule: the newest tag with a dot and the pin's variant
     suffix.
   - Upgrade moves a pin's tag and its multi-arch index digest together.
   - The hold list applies to them as it does to any pin.
2. The defaults are Gotenberg 9.9.3-libreoffice and linuxserver/ffmpeg 9.0.2-cli-ls90. Under them:
   - the integration tier passes;
   - the picture golden sums are unchanged (LibreOffice stays 26.8.2.2);
   - currency reports only the MimeKit 4.18.2 and typed-path 0.12.4 holds.

   No comment or doc states an image version that an upgrade would leave untrue.
3. The releases are prepared:
   - The base module's CHANGELOG has a dated `[v0.4.2]` section stating the moved defaults.
   - storage's and postgres's `[v0.1.1]` sections state their docproc v0.4.1 requirement, which
     stays at v0.4.1.
   - docproc-onenote's `[v0.1.2]` section holds what its Unreleased held, and `--version` prints
     `0.1.2`.
   - cmd/docproc reaches v0.4.2 through a temporary replace until SHIP.
   - The README's install line and tool table name v0.4.2 and `tools/onenote/v0.1.2`.
4. The shared-gs identity check is rerun on all 68 ~/docs PDFs. The candidate's shared path runs
   at concurrency 1 and 4, and the baseline is v0.3.0's per-page path at concurrency 1.
   - Every page line is identical: number, DPI, PNG SHA-256, text SHA-256, name, and error.
   - The six failing PDFs fail as before, word for word.
   - digitally-signed-3d-portfolio.pdf is the one stated exception. Since v0.4.1's portfolio fix,
     its page is the cover.
5. The mail bench is rerun: the spike's findings bench, from a scratch copy at 9cbbdd3, against
   docproc-mail v0.1.4's linux-x64 release archive, verified against `SHA256SUMS`.

   - Each table sits beside acceptance's v0.1.2 and the spike's results, judged equal, better,
     worse, or not comparable.
   - A slower row is recorded, not held to a time bar.
6. cmd/docproc runs over ~/docs as the candidate builds it:
   - Every `DOCPROC_` variable is unset, and the workers are the default.
   - docproc-ooxml v0.1.2 and docproc-mail v0.1.4 run from their release archives, verified
     against `SHA256SUMS`. docproc-onenote v0.1.2 is built by its release recipe.
   - The ~/docs listing (path, size, mtime) is the same before and after.
   - The record states:
     - each tool's version and source;

   commit measured and the tags that commit becomes. It doesn't rerun word error rate, bombs, peak

   rerun. A finding that needs a release this brief doesn't name is escalated.
