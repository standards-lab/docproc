## Task brief · architecture

```
Problem       Go Elemental's sourcing rule offers two choices, write in-house or source a
              library, with no page for the third that merged code already uses: run a mature
              system tool through an adapter. The pages say a provider sub-module doesn't move an
              adjacent library's level, but not that a repository's place follows its base module
              whatever nested command or example modules it carries, and that statement lives on
              two pages, not one. docproc's STANDARDS.md states system-tool lines with no page to
              point to.
Behaviors     1. A go-elemental principle page on system tools states the third sourcing choice:
                 the adapter is the boundary (the system's interface says what it needs, each
                 adapter how one tool provides it); a tool is a process, run directly or in a
                 digest-pinned container; an adapter finds its tool and checks its version when
                 built, and runs it under the caller's context; a tool's license binds the image
                 that ships it. Each claim names the merged code expressing it (herald,
                 spike-ai-pipeline-processing v0.9.0). It links the minimal-footprint page for
                 tool selection, and names no script runner and no unbuilt artifact.
              2. Go Elemental's README and principles index list the page, and the dependencies
                 page's Sourcing links it as the third choice.
              3. The repository-topology page states once that a repository's place follows its
                 base module: a nested provider, command, or example module pins only its own
                 level and doesn't move the repository, as blobfs's example module over
                 go-storage doesn't. The dependencies and tool-beside-library pages link that
                 statement instead of restating it.
              4. The repository-topology page's "Versioning across the tiers" states that a
                 change spanning a repository and a nested module that depends on a later-placed
                 tier releases that tier first.
              5. docproc's STANDARDS.md points to the system-tools page, replacing its bare
                 adapter line and keeping its own narrowings.
              6. The goal record's pending edits drop the system-tools entry and keep the

                 data-intelligence.md entries for the sync, with the sync notes the rounds found.

              detail); docproc's check
Slices        1 architecture: the system-tools page, its index entries, the Sourcing link
              2 architecture: the placement rule's one home, the links replacing restatements,
                the release-order sentence
              3 docproc: the STANDARDS.md pointer, merging after architecture's branch (an
                exception to `order`, which places docproc below architecture)
Out of scope  any code; the nested-command layout; module-zip exclusion by a nested go.mod; CI
              gate jobs and rulesets; the external-repository principle; tools nested in another
              language; coordinator notes (data-intelligence.md); docproc's currency failure
```
