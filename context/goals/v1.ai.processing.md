- coordinator · context/data-intelligence.md: add a summary of quarry's `context/layers.md`, and replace "one event stream per job" with one shared CEREBRO_JOBS stream holding a subject per job. The summary: quarry's `context/layers.md` states each boundary of Cerebro's stack (system tools → quarry → go-ai → Cerebro) as signatures and schemas, each traced to this note's design tasks or to spike evidence. The tool contracts move to schema "2": JSON Lines with Markdown inside as the text layer, grown by addition only from there. Every piece of text a file holds exists once: content in the Markdown text layer, labels (a mail store's name, OneNote's ink alternatives) as kept plain-text fields. A structured field is cut only when its text is already carried, in the Markdown or in a kept field, or it can't be plain text and has no processor, as measured over ~/docs; content a tool reads but leaves out of its Markdown is rendered into it, never kept beside it as a duplicate field. quarry's library exports `infer` (vision, transcription, embedding, and chunker interfaces free of go-ai, a cache, and a pipeline that yields inference texts, batches, and done as made) and `job` (one job's dispatch and inference, cancelled by its own context, storing every output's content and inference text by its SHA-256, and yielding its updates). quarry has no events package, emits no CloudEvents itself, and declares no event kinds, so it has no `messaging.go`; each package that produces a change holds its JSON shapes in its ordinary files, beside its other types (dispatch's parts, outputs, and warnings; infer's inference texts, batches, chunks, done, and profile; job's `Update`, checkpoint, and done, version "1"). quarry's nested `model` module holds the one go-ai adapter to `infer`'s interfaces, which Cerebro and quarry's `cmd/docinfer` both import; Cerebro only wires it. Cerebro starts from Go Elemental Commands (Submit, OpenUpload, AppendChunk, CompleteUpload, AbortUpload, CancelJob) and Queries (GetJob, GetUpload, GetOutput, ListProfiles). JetStream holds the streams CEREBRO_WORK, CEREBRO_JOBS, and CEREBRO_UPLOADS beside an object store (staged inputs, content by SHA-256) and a KV bucket (the cache); each job's events go on one subject of its own in CEREBRO_JOBS, `cerebro.job.<job>`, for the job's gap-free sequence (messaging.md's subject and stream conventions govern a web service's events for committed command mutations, not a job's progress and result stream). Events are CloudEvents 1.0 in binary mode on NATS headers; Cerebro defines their `cerebro.job.*` types in its own `messaging.go` with `event.Define` over quarry's `job.Update` or its own data types, which sit beside its other types. Each attempt's `started` carries the resolved profile; a `completed` event carries the manifest: the job's contiguous sequence range, the batch and chunk counts and a digest over every attempt's batches, and each attempt's counts as quarry reported them. The open items pass to `protocol` (live sources, the small-document size), `events` (the batch cap, large extraction values), `state` (stream and bucket names), `chunks` (storing chunks by identity), `metadata` (typed metadata shapes), `athena-mapping` (typed cells for `sparse_rows`), `text-layer` (OCR text read from the Markdown's image text), and v1.ai.client (transcription retry).
